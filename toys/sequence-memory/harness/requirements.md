**记录页的"分页"落在类型、tie-break 落在组合**（5b 定案）：需求行写的"按组合分页"落地成**按类型分页 + 每组合一张卡**。理由是 tie-break 的两个顺位在 5a 就是**按组合累计**存的（总错次 / 平均复现用时），而即点即判下每局恰好错一次终局、一局的总错次恒为 1，所以"总错次少"只在组合之间才成立（gameplay"达到同一最高长度用的失败次数少"说的就是这个）。另一条路——一组合一页、榜里排该组合的最近 20 局——会让第一顺位变成死键，还得给每局各存一份 ms / taps（存档 schema 扩容），而且"休闲单独一栏不混排行"会跟着变成空话：那条只有在一个列表本来会混进休闲时才承重。认下的代价：一个类型只有两个冲榜档，排序结果多数时候一眼看不出来（两档最高相同才轮到 tie-break）；曲线画给哪一张卡留给 5c 定（5b 的卡不接输入——当时做"选中一张卡"就是个点了没反应的控件，比置灰更像 bug；5c 给了它反应，见下条）。

**曲线画给选中的那一张卡**（5c 定案）：另一条路是每张卡各带一条迷你曲线（不新增交互、三档趋势一眼看全），认不下的是两笔账——**横屏塞不进**：844×390 右列的预算 281、三张卡按最小排布就要 230 上下，480×320 的预算 223 更是刚好被吃完，三块图只能整块砍掉，于是手机横屏压根看不到曲线；**迷你图带不动需求里那条参考线**：26px 高的图上"历史最高"只剩一根看不出的横线，标签与纵轴刻度都没地方放。所以选一张卡：卡改成可选（点一下换曲线，回响 = UI 音 + 左侧强调条 + 整块重画），一页只画一条也正好守住"不同组合不可比"——三条并排是在邀请比较。**横屏曲线归左列**（标题 / 总说明与页脚之间，左列宽 192 / 231 / 348，高吃两列之间剩下的、封顶到目标块高），右列在最紧那几档视口上没有它的位置；竖屏排在三张卡下面（宽 = 内容列宽）。**降级阶梯多一级"砍曲线"，而且曲线的高度要先划出来再让卡片跑阶梯**：反过来的话，320×568 这类小屏上明明把数字降一级字号就放得下的曲线会被整块砍掉。**结算不放曲线**：gameplay 反馈节原来把曲线列成结算第 5 项，那是 1m 瘦身之前写的——1m 之后结算是"大字 + 逐位对照 + 诊断一行"那一屏，横屏回放本来就在跟高度预算打架，再塞一块图会把回放格子压到 18px 下限；已改 gameplay。

**参照只给冲榜档，其余落回"历史第几好"**（5d 定案）：另一条路是每一档都查常模（含休闲），认不下的是**量纲**——休闲是累积追加、每轮重播旧序列，而重播允许复述，分数随练习膨胀（gameplay 模式表里那句就是它），拿一个复述出来的 15 去查"数字广度 7 ± 1.5"就是把练习效应说成能力，正撞在措辞红线上；而"休闲单独一栏不混排行"本来就是同源的一条纪律（休闲成绩不与任何榜 / 常模混）。所以休闲与无常模的类型（扑克 / 颜色）一律落回"这一局在最近 N 局里排第 K 好"。**记录页只有冲榜档的卡有常模句**：卡上的数字是"最高"，而最高在自己的历史里恒为第 1 好，"历史第几好"在记录页没有信息量（它只在结算说得出口，那里说的是这一局）；于是扑克与颜色两页一个字不提常模，页脚那句标注也只出现在数字 / 位置两页。**破纪录时不重复"第 1 好"**（新纪录徽标与"超过它 N 项"那行已经说完了，1m 那条"砍的只是重复句子"），**0 分局两种参照都不给**（没有成绩可比，不是垫底）。认下的代价：挑战档是快档、呈现比常模快，百分位偏保守（低估玩家）——低估是红线要的那一侧，与天花板效应一起认下，不另做映射。

**教学关改判为静态"玩法"页**（7 改判；同批删掉 6 / 8a / 8b / 8c，理由各见其行）：长解释必须有地方住——1m 把它们从结算搬走、局内短提示也不许带规则，账都记在教学关上（ui.md 两条纪律与 GameScene / GameOverScene 的注释都是这么写的），所以 7 不能整条删，只能改判。**不做可玩脚本关**：规则一共五句（呈现 → 隐藏 → 按序点回 → 点错即终 → 得分 = 最大全对长度），三段相位与物件反馈自己就在教（ui.md 原则 2"物件先说话"），强制关只是把第一局真玩往后推，还多一套首次判定与已读标记要验。**不做强制拦截**：首页给常驻入口，是否首次自动打开一次留给人点决定；真要也只是一个本地布尔——原 #9 的 localStorage + sessionStorage 双层兜底随之收口，隐私模式下每次都打开也接受。阶梯定位表少一档（教学关那一档），PRESETS 不受影响：它从来不是玩法档。

**休闲与冲榜同走即点即判**（3b 已取消）：休闲 = 累积追加 + 里程碑提速 + 点错即终，没有退格、没有容错重试——错了再来一局就好，不必在同一局上死磕。判定两模式两方向都相同，差别只在生成方式、方向与速度档（都是"玩什么"），所以首页那句模式说明描述生成与方向、不提判定，这是最终形态不是过渡态的权宜。以后真有退格 / 容错诉求再开阶段（见 3b 行）。

**色盲模式不做开关**（4b 已收缩）：非颜色身份通道不是"模式"，是常驻设计——颜色四块各配固定形状（圆 / 方 / 三角 / 菱），呈现台与复现棋盘两端都画、亮起时标记转白形状仍在；四色避开红 / 绿对；诊断行符号名自带形状（"蓝（圆形）"）；扑克靠四花色轮廓两两可分、tab"当前"态另有顶部指示条、已选是压暗不是换色；结算三态靠破折号与"期望 / 输入"两行的符号差；点错另有抖动 + hit stop + 低鸣三条非颜色通道。**开关打开后画面没有可见变化，这比没有开关更糟**（玩家会怀疑没生效），而它照样要占设置页一行 + 持久化 + 文案 + 验收面。真要给这个模式加内容只有两条，都不做：① 色块印文字 / 字母——与"位置九格不印方位，印了会变成可默念任务"同一条纪律冲突，把视觉身份任务降级成命名任务；② 换一套色盲安全色板——形状已常驻不增益，还要第二套 tint 路径，且推翻 ui.md"四色本身不换"。`defaultSettings.colorBlind` 这个无人读的死字段随之删除。以后真发现某一处只靠颜色（结算三态的"错"就是这次补出来的那一处），按局部修法补非颜色通道，不开全局模式。

**声音开关已收进设置页**（4a 定案暂住首页，4c 搬走）：设置页只放全局偏好——音效 / 音调（4a 落地）+ 起始长度 / 进度点（4c 落地），玩法档仍在首页。四项都照走纪律 1：本地持久化（systems/Prefs，读值按键型校验、写不进退回内存）、开局由 Setup.snapshot 合并进快照、局内只读快照不回读 Prefs——所以局中改不了，下一局才生效；冲榜与挑战的起始长度在 snapshot 锁回 2（记录可比），起始长度离散三档 2–4、上限低于第一个里程碑 5（否则开局即提速，"提速被看见"失效）。音调开时颜色类型的**呈现亮起与点对**都按色定音高（config.COLOR_TONES 四固定音高，与 COLORS 同序），打开开关当场预览四音。特效契约的视觉列在 1i–3c 已逐行落地，4a 逐行核对无缺口，补的是声音列（开关门控 / 四音调 / 预览）。
