# harness — AI 开发上下文

本目录是 sequence-memory 的唯一文档来源，**面向 AI、配合代码阅读**：只保留粗线条的需求、规则、设计意图与约束，**实现细节一律以代码为准**。

## 读取顺序

1. `requirements.md` — 做什么、做到哪了、下一步做什么、验收点、未决问题。
2. `gameplay.md` — 玩法规则（需求的内容细节：判定 / 计分 / 反馈 / 红线 / 不做清单）。
3. `ui.md` — UI 原则与设计意图（长什么样、怎么动、怎么回应输入）。
4. `architecture.md` — 文件组织、分层约束、技术定案、已知坑。
5. 代码 — 具体数值、几何、画法、时序。文档与代码在细节上冲突时以代码为准。

工程纪律（测试 / 验证边界 / 依赖 / 提交）在同级 `../AGENTS.md`。

## 维护规则

- **需求先行，实现时再设计。** 文档只定"要什么功能 / 效果"，不提前定死"怎么做"。未实现的功能不写实现方案；轮到某一步时，按当时的代码与需求现状重新设计，做完把结论中仍然有效的约束沉淀回本目录。
- **改玩法先改 `gameplay.md`，改外观与交互先改 `ui.md`，再动代码。** 需求或约束变了先改文档；纯实现细节变了不必回写文档。
- 每完成一个阶段，把 `requirements.md` 总表对应行的状态改成 ✅；被推翻的定案直接删改，不留作废红线误导下一次判断。
- `static/` 被 Hugo 原样发布，本目录上线后公开可读，只写设计取舍，不写敏感信息。
