# 玩法规则

> 需求的内容细节：玩什么、怎么判定、怎么算分。不谈实现。核心一句：**"反应 + 键位熟练度"游戏，不是"打字速度"游戏——难度来自下落速度 × 字母池两个主维度，同屏数量刻意不堆高。** 意象是流星：下落天然、高速天然、"击落 → 炸成星屑"情绪链现成，危险线是地平线（坠落 = 失败自带解释）。

## 核心循环

星星顶部生成 → 带光尾摇摆匀速下落 → 敲对应字母键：命中爆开飘分连击 +1；按错只清连击降准确率（**不扣分不扣命**，扣分让人不敢出手；想要代价的人开严格模式，见计分节）；落到地平线坠毁扣一条命。生命归零 → 结算 → 再来一局 / 换难度 / 回菜单。

## 判定

| 规则 | 设定 |
| --- | --- |
| 重复字母消歧 | 敲 `a` 打掉所有 `a` 里**最靠近地平线那颗**（最紧迫优先，不需精确瞄准）；最低那颗亮白脉冲描边让规则看得见。**判定与脉冲必须同一份计算** |
| 键位来源 | `event.code` 不是 `event.key`（免疫大小写 / Shift / Caps / 输入法）；过滤 `event.repeat`（长按不连爆）；ctrl/meta/alt 按下不计失误，Shift 不排除 |
| 控制键 | Esc 暂停、`` ` `` 参考线（隐藏快捷键，无按钮入口）、`\` 回菜单——**必须全在字母池外**（否则 `p` 星永远打不掉），其余非池键忽略不计失误；小键盘不认 |
| 防重叠 | 生成时水平 <64px 且垂直 <80px 内已有星则重采样（最多 8 次），仍失败本次跳过，不放宽硬约束 |
| 黑洞分流 | 黑洞照常参与最低优先（白圈诚实指向它），命中后走误敲分支不走命中特效。**生成侧保证黑洞与非黑洞不共享字母**（见特殊星节），所以"按了扣命、不按也扣命"的无解局面不会出现 |
| 触屏降级 | 点中一颗星 = 敲它的**下一个待敲键**（键位方案里就是星面显示的那个字母），喂进与键盘**同一份判定**（最低优先 / 黑洞误敲 / 双星顺序全同，统计口径因此一致）；点双星还没轮到那颗就是顺序错，点重复字母里偏高那颗掉的仍是最低那颗。点空白不计失误（没有字母可判），装饰流星点不动（6e） |

### 键序判定（9d）

判定泛化为**键序**：每颗星携带「显示面 + 键序 + 进度」，普通字母星是单键特例（键序长 1），双星是两键特例，9e/9f/9g 的序列星是多键单体。**白圈与最低优先消歧认「下一个待敲键」**——9g 起它是一个**集合**（多音字每条读音各给一个候选键，见下），单键星与单读音星退化成只有一个元素的集合，所以 `letters.js` 的 lowestMatch / markTargets 仍是唯一一份口径，白圈永远指向敲了有用的星。

| 敲键结果 | 规则 |
| --- | --- |
| 敲对任一待敲键、且不是最后一键 | 进度推进一格，**不计分、不动连击、不推进爬升**，星留在场上（双星首颗变暗 / 连线缩短 / 第二颗放大就是这条的视觉落地） |
| 敲对最后一键 | 整颗消除，按类型计一次击落（双星 +30、金色 +50…），五件套齐发 |
| 敲错（没有任何一条读音的待敲键匹配） | 记一次失误、断连击，**进度绝不回退**——已经敲对的那几键不作废（双星"顺序敲错两颗都不消除"是它的两键特例） |

键序引擎收在 `utils/sequence.js`（纯逻辑，Node 可测）：键序状态 = `{ paths, depth }`——`paths` 是**仍然存活的那几条读音**（每敲对一键就按它过滤一次），`depth` 是已经敲对的键数。`nextKeys` / `pendingKey` / `isLast` / `advance(seq, key)` / `isLaterKey` / `total` 几个纯函数。推进只前进不回退；"敲错记失误"由判定层在**不匹配**时走 miss 分支保证，引擎本身不吃错键（`advance` 收到不匹配的键直接返回 false 且不改状态）。顺序错诊断（读数写清"要先敲 X"）用 `isLaterKey`：敲的是这颗星还没轮到的后续键 ⇒ 无匹配，但要说清是顺序问题而不是屏幕上没这个键。

**显示面与键序的关系**：键位方案（标准 / 字母 / 数字 / 符号）的显示面就是键序字符本身——单键星一个字母、双星两颗各一个字母。**单元方案（9e 起）的显示面与键序分离**：一个星体装一个完整单元，键序藏在内。

| 规则 | 设定 |
| --- | --- |
| 星面绝不显示键 | 显示键 = 抄答案，训练价值归零。显示面必须是"能推出键序、但不是键序本身"的东西：汉字（9e / 9g）或音节（9f） |
| 进度反馈在星体内部 | 一排进度点画在星体自己身上，敲对一键亮一格；**不用线连多星**（线连是双星那套两键特例的造型）。点只说"敲到第几键"，不透露是哪一键 |
| 一个单元 = 一个整体 | 占一个同屏名额、坠毁只扣**一条**命、敲完只算**一次击落**（与双星同一条口径）；中间那几键不计分、不动连击、不推进爬升 |
| 敲错进度不回退 | 已亮的那几格不灭——键序引擎的通则（见上表），双星"顺序错两颗都不消除"是它的两键特例 |

### 多音字：任一读音都算对（9g）

**一个多音字的星，玩家敲它任何一个读音都能消除**——这个方案练的是打字不是正音：真实输入法里「行」打 xing 或 hang 都出字，钉死一个读音是在教一件打字时用不上的事，还会逼玩家猜。所以 9e 那条"多音字只收各读音字母串相同的"约束放宽成"**各读音等长就收**"，字母串不同的（行 / 长 / 重 / 地…）也能进字表了。

| 规则 | 设定 |
| --- | --- |
| 只收**各读音等长**的多音字 | 等长 ⇒ 两条读音不可能互为前缀 ⇒ **消除时机唯一**（不会出现"敲完 de 时 dei 还差一键、星该不该炸"）⇒ 进度点总数恒有定义；等长也 ⇒ 没有短读音可挑，"一个单元 = 一次击落"的计分不会被"挑最短读音"这个退化最优解污染。不等长的一律不收：会 hui/kuai、得 de/dei、石 shi/dan、大 da/dai、车 che/ju、还 hai/huan、没 mei/mo、六 liu/lu、给 gei/ji、似 si/shi、宿 su/xiu、削 xue/xiao |
| 敲对第一键就锁定那条读音 | 存活路径按敲下的键过滤：「行」敲 x 之后只剩 xing，再敲 a 就是失误（hang 那条已经死了）。**进度不回退**这条通则照旧 |
| 进度点数 = 该字的键数 | 等长所以唯一，多音字与单音字画法完全一样，9e 已验收的点排几何一行不动 |
| 白圈只在"敲我任何一个候选键都掉我"时亮 | 多音字星的候选键可能只对其中一个是最低（「行」在上、「好」在下：敲 h 掉「好」、敲 x 掉「行」）。此时**那颗多音字星不亮圈**——亮起来等于说"敲 h 也掉我"，是撒谎；宁可少亮。「好」照旧亮（它对 h 是最低、且 h 确实与别人共享） |
| 同屏候选键上限给每个候选键都算 | 多音字星占它**每个**待敲键的名额，所以生成侧要求"这个字的每个首键都没满"才放它出场 |
| 触屏只走规范读音 | "点一颗星 = 敲它的下一个待敲键"在多读音下没有唯一答案，取读音表里第一条。触屏本来就是降级路径，代价记在案 |
| 上飘的字必须是玩家真敲下的那一键 | 推进那一下飘"刚被吃掉的那一键"（ui.md 反馈契约）——多音字星的规范键可能不是玩家敲的那个，所以判定层用按下的键覆写快照，飘出来的是 h 不是 x |

**双拼方案天然满足等长**（恒 2 键），所以多音字在双拼里没有收字限制；只是 `flypy` 的内容串目前不含任何多音字，行为与 9f 逐字相同，版本因此不动（config.test 钉住这条）。

## 计分与连击

单次得分 = round((基础 10 + 紧迫奖励 + 类型奖励) × 连击倍率)。紧迫奖励按画面三等分：上 0 / 中 +5 / 下 +10（鼓励 clutch）。倍率五档：0–4 → 1×、5–9 → 1.5×、10–19 → 2×、20–39 → 3×、40+ → 4×，**先 combo++ 再查表**（第 5 击本身吃 1.5×）。中断条件：按错、坠毁、误敲黑洞；中断不扣分。

**严格模式**（设置开关，默认关，6c）：按错另扣一次基础分（10 分，config.STRICT_MISS_PENALTY），**扣到 0 为止不为负**。"按错"指所有记失误的键：无匹配、双星顺序错、误敲黑洞——三者同罚；坠毁不扣分（已经扣了一条命，不再叠罚）。倍率与连击规则不变，罚分不吃倍率。开关吃**开局快照**：设置入口只在菜单，局中改不了，下一局才生效。

结算统计八项：得分 / 击落 / 失误（按错字母键次数，含误敲黑洞）/ 坠毁 / 准确率（击落 ÷ 三者之和）/ 最高连击 / 用时 / 手速（击落/分，不用 WPM）。**只有生命耗尽的完整一局入档**，中途退出不占最高分不计局数。最高分按「**方案 × 玩法 × 档位**」分记，互不串号（9a）：方案带版本，记录键含版本，规则变更 bump 版本后旧记录自然封存、不与新规则混算；9a 之前的旧键「档位-玩法」升级时原样并进标准方案当前版本，旧最高分升级后原样可读。累计三项（局数 / 击落 / 最高连击）仍是全局一份，不分方案。**排行榜按方案分栏展示（9b）**：栏内「玩法 × 档位」记录表，跨方案分数不并列比较、不做归一化总榜——内容不同的方案分数没有可比性。入榜纪律：模式弹层里都是定死规则的方案、都入榜；将来若加方案内自由筛选，属练习配置、不入榜。

## 特殊星

打破"每颗都一样"，制造"先识别再敲"的判断。**类型表驱动：加类型 = 添表行 + 造型，流程不改。**

| 类型 | 权重 | 行为 | 得分 | 误操作 |
| --- | --- | --- | --- | --- |
| 普通星 | 82% | 标准下落，随机五色（**不含金**，金是金色星身份色） | 基础 | — |
| 金色星 | 6% | 自身下落 ×1.3 | +50（参与倍率） | — |
| 冰晶星 | 5% | 标准下落；命中后**全场** 4 秒所有星 ×0.5 | +20 | — |
| 黑洞 | 5%（Lv3+，**不进单元方案**） | 标准下落；**不能敲，让它落下去零惩罚**（不扣命不算坠毁不断连击） | 0 | 敲了 → 命 −1 + 失误 +1 + 断连击，全局最重反馈 |
| 双星 | 2%（Lv3+，**仅标准方案**） | 一线连两颗各带一字母，**按顺序**敲完才消除 | +30 | 顺序敲错记一次失误、不消除 |

- 冰晶的 ×0.5 是给**别的星**的全场减速，不是自己慢（自身 speedMul = 1）；连命中两颗**只重置计时不叠加**（不 ×0.25、不 8 秒）；4 秒是墙上时间不吃 hit stop。
- 黑洞是最重要的反单调元素，也最劝退新手：Lv1–2 不出现；说明页专讲"落下去不扣命"这半条（玩家本能是"落下去扣命所以必须敲"）；首颗真黑洞生成时一次性琥珀横幅提示（写 voidSeen 后不再触发，不做慢放——与 hit stop 共用 slow 状态会叠成长停顿）。
- 双星是键序判定的**两键特例**（9d）：线连造型保留，**仅标准方案使用**——专练与单元方案（9e/9f/9g）用单体序列星，不挂线连造型。门禁在方案注册表的 `pair` 标志，`levelFor` 合成生效档位时按类型表的 `pair` 过滤 specials，生成 / 判定流程不认识方案。
- **黑洞不进单元方案**（9e）：门禁与双星同一条套路——类型表加 `unit` 标志（普通 / 金色 / 冰晶为 true，黑洞 / 双星为 false），`levelFor` 按方案的 `unit` 标志过滤，单元方案 Lv3+ 只有金 / 冰两类。理由是黑洞的字母隔离在多键星上做不出完备保证：要完备就得排除在场每颗单元星的**全部剩余键**（8 颗 × 4–6 键的并集轻松覆盖 26 个字母 ⇒ 黑洞永远生不出来，或整拍跳光）；只排首键则留下一个新陷阱——单元星推进到某一键时，若在场黑洞的下一键相同且更低，敲它就走误敲分支扣一条命，**玩家按对了却掉命**，直接违反"按错只清连击不扣命"（判定侧改不了：误敲分流必须排在键序分流之前，否则黑洞可以用"假装顺序错"绕开）。9g 若要请回黑洞，先给键序引擎补一个"剩余键"读口，并验排除集饱和时整拍跳过不放宽——**多音字（9g）让这笔账更难算**：一颗「行」的剩余键是 xing 与 hang 两条路的并集，排除集饱和得更快。
- 双星是**一个整体**：占一个同屏名额、坠毁只扣**一条**命、敲完只算**一次击落**（+30 参与倍率、连击 +1、爬升 +1）。第一颗敲对**不计分也不动连击**——它只把顺序推进到第二颗；一对 = 两次正确按键换一次击落，手速因此略低是预期。
- 双星的判定只认**轮到敲的那一颗**：它参与最低优先消歧与白圈，还没轮到的那颗**不是目标**（白圈永远不会指向一颗敲了没用的星），敲它等于无匹配 ⇒ 记一次失误、两颗都不消除。这就是"顺序敲错"的落地方式，判定侧不需要第二套规则。
- 一对的两个字母必然不同（第二个接着第一个挑），两颗都算进"同屏同字母 ≤2"——还没轮到的那颗也占着一个字母位。
- 加权生成（5e 已接入）：按上表权重抽类型，难度开关决定候选（Lv1 无 / Lv2 金+冰 / Lv3+ 全部）；Lv5 **特殊星权重加倍、普通星不加倍**。
- **同屏特殊星 ≤2**（双星算一个整体、占一个名额）：配额满了这一颗回落普通星，不跳过这一拍——生成节奏不因特殊星配额断档。
- **黑洞字母隔离**（生成侧硬约束）：黑洞的字母不能与任何在场非黑洞星（普通 / 金色 / 冰晶 / 双星含 pending）的字母相同；反之，非黑洞星的字母不能与在场黑洞的字母相同。目的：消除"上面普通星要救、下面黑洞同字母不能按"的无解陷阱。判定侧（lowestMatch / 白圈 / 触屏）一行不动——隔离在生成时已保证，判定时同字母里不会混着黑洞与普通星。字母池 ≥10、同屏特殊星 ≤2，排除 1–2 个字母对生成节奏无感（专练的符号池只有 9 键，排除集偶尔清空候选时整拍跳过，见方案内容梯度表）。

## 难度：档位管物理，方案管内容（9a 拆分）

**档位（入门–大师）只管物理与高速可读性补偿**——速度 / 反应窗口 / 间隔 / 同屏上限 / 命 / 特殊星开关与加倍 / 字号 / 描边，五档被所有方案共享（真值在 config.js `LEVELS`）。**"出什么内容"归各方案自带的「档位 → 内容」梯度表**（config.js `SCHEMES`）：改档位物理所有方案同步生效，改某方案内容表不影响别的方案。判定与计分不认识方案，只认识合成后的字母池——`levelFor(方案, 档位)` 把档位物理与方案内容合成一份「本局生效档位」，下游照旧读 `level.pool`。

### 专练方案（9c）：字母 / 数字 / 符号

三个独立方案注册进弹层，各有内容梯度与独立记录线。**数字与符号在入门档就出对应内容**——专练的目的就是不必开大师速度也能练到它们，档位只提速：

| 方案 | Lv1 | Lv2 | Lv3 | Lv4 | Lv5 |
| --- | --- | --- | --- | --- | --- |
| 字母 `letters` | 中排字母 9 键（不含 `;`） | +上排 19 | 全小写 26 | 26 | 26 |
| 数字 `digits` | 0–9 共 10 键 | 10 | 10 | 10 | 10 |
| 符号 `symbols` | `-=[]',./;` 共 9 键 | 9 | 9 | 9 | 9 |

- **字母专练任何档位不出数字与符号**：`;` 虽在中排但属符号键，从字母池里剔除（所以 Lv1 是 9 键不是 10）。Lv3 起池封顶 26，高档只提速。
- 数字 / 符号专练五档内容恒定：梯度表退化成一行，难度全由共享档位的物理给。三方案与标准方案的记录互不串号——记录键含方案 id，合法键集随注册表自动扩成 4 × 5 × 2 = 40 个，标准方案的键与版本一个没动。
- **专练不出双星**（9d）：线连双星仅标准方案使用，三个专练方案的 `pair` 标志为 false，`levelFor` 把 'double' 从合成档位的 specials 里滤掉——Lv3+ 也只有金 / 冰 / 黑洞三类特殊星。专练的多键训练留给 9e/9f/9g 的单体序列星。
- **符号池只有 9 键**（`` ` `` 与 `\` 是控制键必须留在池外，物理符号键就这 9 个），比标准方案最小的 10 键还窄：Lv3+ 出黑洞时隔离排除集偶尔清空候选，按既有纪律整拍跳过、不放宽（见特殊星节）。符号键全在右手，"连续同手 40%"在纯符号池里自然退化为全同手（pickLetter 异手候选为空的分支兜住）。
- 加权口径不变：字母仍按英文频率，数字符号平权——纯数字 / 纯符号池里平权就是均匀分布。

### 单元方案（9e）：汉字

一个星体装一个完整单元，键序是它的无调拼音（`好` = h-a-o）。方案注册表添一行（`hanzi`，version 1）就接进弹层 / 排行榜 / 记录线，判定与计分一行未改；造型见 ui.md 的单体序列星节。

| Lv | 内容梯度（按**键序长度**，逐档累加） |
| --- | --- |
| 1 | 2–3 键，28 字 |
| 2 | 2–3 键，字数加到 43 |
| 3 | 加入 4 键，66 字 |
| 4 | 加入 5 键，83 字 |
| 5 | 加入 6 键，94 字（zhuang / chuang / shuang 就是全部三个 6 键音节，收字见下） |

- **字表三条收字约束**：① **多音字只收各读音等长的**（9g 放宽，原先是"字母串相同才收"）——等长 ⇒ 不互为前缀 ⇒ 消除时机唯一、进度点数有定义、没有短读音可挑，于是玩家敲任一读音都算对而游戏仍然确定（全文见「多音字」节；`好` hǎo / hào 字母串相同、`行` xíng / háng 与 `长` cháng / zhǎng 等长，都收；`会` `得` `石` `大` `车` 不等长，不收）；② **不收 ü**（lü / nü 的转写约定仍是 9g 未落地的定案，现在收了就是让玩家猜；ju / qu / xu / yu 不在此列，它们的键盘形式本来就是 u）；③ 键全在 a–z、不带调号、不带分隔符。
- **梯度按键序长度走，不按字的生僻度**：9e 压测的是造型与判定，9g 这一版只放宽多音字、没换梯度轴；常用字 → 生僻字那条内容梯度仍是 9g 剩下的事。
- **字母池四约束里有两条在单元层不套用**：英文频率加权与 40% 异手交替都是**键**层的规则。把首字母的英文频率套到汉字上，会造出"`人` ren 因为 r 频率高而比 `马` ma 多两倍"这种既不是字频也不是设计的偏差；一个汉字的拼音天然跨两手，在首键上做异手交替筛出来的是拼音首字母分布的扭曲，与指法训练无关。保留的两条是：不连续重复同一个字、**同屏「下一个待敲键」相同 ≤2**——待敲键是唯一会被敲到的那一键，按它算正是最低优先消歧的口径（双星把还没轮到那颗也计入，是因为那颗**看得见**；单元星的后续键藏在显示面里，数它只会白白收紧生成）。**9g 起多音字星占它每个候选首键的名额**：生成侧要求"这个字的每个首键都没满"才放它出场，否则白圈会在两个都接受该键的星之间撒谎。9g 若要字频加权，另立一张真字频表。
- **击落数 = 单元数，不是按键数**：一个 6 键单元换一次击落，手速（击落/分）因此天然低于键位方案——跨方案本来就不并列比较（记录键含方案 id）。给不给按键数奖励是 9g 的计分定案，9e 不动计分。
- 每档字数别太窄（Lv1 ≥ 14）：字表窄 + 首键扎堆会让候选清空、整拍跳过，`?debug=1` 的生成跳过计数会涨。

### 双拼方案（9f）：小鹤双拼

一个星体装一个音节，键序是它的**小鹤双拼编码——恒两键**（声母键 + 韵母键）。方案注册表添一行（`flypy`，version 1，`unit: true`、`shuangpin: FLYPY`）就接进弹层 / 排行榜 / 记录线，判定与计分一行未改；造型**复用 9e 的单体序列星**（见 ui.md），不另立造型。

- **星面用汉字，不用音节**（9f 的造型定案，需求原留两条路）：音节面是拉丁多格，6 格在 96 星体上撞 18px 面字号红线（`unitFaceSize(level, 6)` 如实报塞不下），要塞下得把星体升到 ~160+，牵动一串已验收几何。汉字面单格，逐字复用 9e 已验收的造型（96 星体、2 个进度点），零几何风险。训练路径成立：星面一个汉字 → 回忆拼音 → 编码成双拼两键，正是真实双拼打字的心智路径，与汉字方案（全拼连打）清晰区分。**代价如实记**：汉字面受「可读的字」限制，内容覆盖常用 → 较广音节；**映射表本身**独立覆盖全部合法音节（无死键，config.test 守），生僻音节的可读字面是 9g 的事。
- **映射规则**（`FLYPY` 表定死、带版本）：声母 `zh→v / ch→i / sh→u`，其余单字母声母照本键；韵母 a→a o→o e→e i→i u→u v(ü)→v、ai→d ei→w ao→c ou→z、an→j en→f ang→h eng→g er→r、ong/iong→s、iu→q ie→p in→b iao→n ian→m ing/uai→k、ia/ua→x、iang/uang→l、uo→o、ui→v、un→y、uan/üan→r、üe(ue/ve)→t。**零声母**统一走「首字母 + 韵母键」（a→aa、o→oo、e→ee、ai→ad、er→er、ou→oz），无特例。**ü**：lü/nü 键盘形式 lv/nv（韵母 v→v）、lüe/nüe 形式 lve/nve（ve→t）；ju/qu/xu/yu 键盘形式本就用 u。**缩写** iu/ui/un 由韵母表直接覆盖。音节切分先查 zh/ch/sh 两字母声母、再查单字母声母、否则零声母。
- **映射表覆盖全部合法音节、码字唯一**（`SYLLABLES` 412 个，config.test 逐音节验编码为 2 个 a–z 键且全局无碰撞）。唯一碰撞 `lo`(咯) 与 `luo`(罗) 都 → `lo`（flypy 把 o/uo 都映到 O）：`lo` 是边缘口语 particle 音节，**从音节表剔除**（同汉字方案不收 ü / 多音字的取舍）。
- **换映射方案 = 注册新方案，不改本方案**：编码器 `encodeShuangpin(syllable, map)` 的 map 是入参，自然码 / 微软双拼 = 另写一张 map 注册成新方案，flypy 的表与记录线不动。
- **内容梯度按音节常用度**（常用音节 → 较广音节），不按键序长度——双拼恒 2 键，键长分档对它无意义。内容复用汉字方案那张已 vetted 读音的字表，按音节常用度重排成五档累加串（14 → 26 → 39 → 54 → 75 字）。
- 击落数 = 单元数、一个单元 = 一次击落、敲错进度不回退、同屏首键 ≤2、不连续重复同一个字、黑洞与双星不进——全部沿用单元方案通则（见上节与特殊星节）。

- **理论同屏恒 4–5，难度全靠速度（窗口 8.6→2.7s）与内容池（标准方案 10→45 键）**，不靠密度——堆高了屏幕糊。上限是防堆叠保险，真正被节流的是 Lv1（入门反而更宽松）。
- 高速档可读性补偿：字号 32/34 + 描边加粗、光尾随速度加密、近地平线（下 1/5）位移 ×0.92 + 暖橘描边与光晕加亮。**减速描边（暖橘）与命中描边（白）必须是两种东西**，同时成立白圈优先——白脉冲 = "敲这个字母掉的就是它"是判定可读性地基。单元方案的星面另有可读性红线（最小面字号 + 星体尺寸，见 ui.md 单体序列星节）：汉字按面积读，不能照抄拉丁字号。
- 无尽模式局内爬升：每 15 次击落速度 ×1.06、间隔 ×0.95，封顶 1.8× / 0.4×，**已在场的星一起提速**；闯关完全不爬升。爬升是派生值，**绝不写回共享表**。
- 字母池四约束：不连续重复 / 连续同手概率降到 40%（频率加权放在"手内"）/ 同屏同字母 ≤2 / 英文频率加权（数字符号平权）。加权必须跑大样本打印实际分布验证，不靠感觉。**这四条是键位方案的口径**；单元方案只保留其中两条（见单元方案节）。

## 流程与教学

Boot → 菜单（选档即开局，无单独"开始"按钮；玩法 × 方案在模式弹层里选，9b，选择持久化刷新保留）→ 3 秒倒计时缓冲（敲键不计失误、用时不含缓冲、生成器未启动）→ 游戏 ⇄ 暂停（Esc 主动；失焦 / 切后台自动进暂停，6d，缓冲期同样暂停）→ 结算三出口（R 再来 / E 换难度带预选 / M 回菜单）。倒计时信息条、暂停与结算的本局信息都带方案名——多方案时玩家要能确认自己练的是哪一套内容。

**不做交互式教学**（4d 已取消）：静态玩法说明即最终形态（**页数随规则增补，9e 起五页**），菜单 T 随时可重看。规则靠玩学会——Lv1 第一颗星 8.6s 窗口、脉冲描边当场教消歧、扣命有碎裂 + 闪光 + 震屏。说明页必须含三条不可自行推断的规则：坠毁扣命 / 按错不扣命只清连击 / 黑洞落下去不扣命。**双星占第四页**（"先敲哪一颗"同样不可自行推断，示意图必须与真实造型同比例：大那颗先敲、箭头指向下一颗）。**序列星占第五页**（9e，"星面是字不是键"同样不可自行推断：示意图读与真实星体同一份常量，星面一个汉字 + 那排进度点，箭头指向它的拼音键）。**多音字"任一读音都算对"写在第五页那句补充里、不单独占页**（9g）：它是"比预期更宽松"而不是"更严格"，敲对了当场就知道；但不写的话，不知道某个字还有第二个读音的人只会以为自己拼错了。示意图仍是单读音的「好」= h-a-o（画两条并行键序会把"一个字一串键"这件主要的事讲糊）。第一步那句"星星上的字母就是你要敲的键"因此不再普遍成立，就地加一句限定指向第五页。**冰晶不进说明页**（命中即好处，画面自解释）；不首次自动弹出（文字墙推迟第一次命中）。

## 明确不做

向上飞的意象（丧失逼近压迫感）、气球等轻飘意象（撑不住高速档）、同屏堆密度、按错扣分（默认）、交互式教学、首次自动弹说明、词条模式（改星座模式且可选）、小键盘判定。
